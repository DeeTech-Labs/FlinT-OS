OS: `a7ede1d0563f014995d046497b0605e3595266ef`. SDK: `9d768efc36df3c974c57c1d02211af1d1875bea7`.
Приложение: 751856 байт, 28% свободно в OTA-разделе 1 MiB. SHA-256 ELF из descriptor, совпавший с `hello` платы: `0c61e1c53232257a2723072fbffbc8075a3051d42afddcbfb8833f59724c46bd`.
SHA-256 записанного `flint_os.bin`: `dd3a434a1fec25cf88b4de252ec9a08d41d0fdb4f7e23341e70d0f5b459818d0`.

## Сценарий и измерения

По USB FLCP установлено отдельное тестовое приложение на базе SDK `examples/icons` (13814 байт), показана сцена с тремя ResourceImage: INDEX8, A4 и RGB565+A8. Launcher показал три CatalogIcon. После этого выполнено 12 циклов Settings → тестовое приложение → Launcher → Clock. Получено 52 снимка diagnostics, включая исходное/восстановленное состояние. Между launch и снимком была пауза 120 мс; накопительные счётчики включают подготовительный прогон в том же boot. Установка заняла 2547 мс по времени host, включая USB, hash и публикацию; это не чистое время чтения иконки.

Монотонного снижения свободной памяти в этих 12 циклах не наблюдалось: первый/последний Clock — 183727/183771 байт. Это ограниченный прогон, не доказательство отсутствия всех утечек. Минимум internal heap за boot — 96296 байт; минимальный наблюдаемый largest block — 64512 байт. PSRAM free во всех снимках — 1959796 байт, исторический минимум — 1942896. Минимальный watermark основного task stack — 18044 байт. Это показатели всей прошивки, а не изолированный peak декодера.

Ошибки display, recovery, resource read, request и `last_logic_error` — 0. Тестовый пакет удалён; набор пакетов до/после совпал (9); исходный экран восстановлен. Сырые диагностики и резервная копия хранятся только локально в `temp/` и не публикуются.

## Время: обнаруженное ограничение

Холодный вход в Launcher дал накопительный максимум полного frame **728234 мкс**. Максимум raster — **494968 мкс**, SPI — **31266 мкс**. Эти интервалы вложены друг в друга, их нельзя складывать. Между соседними снимками среднее по фактически нарисованным кадрам `paint_total_us / paint_count` для повторных входов составило: Launcher 478704–494948 мкс, Settings 50637–50727, три изображения 31603–31801, Clock 21494–21742. Каждый новый запуск launcher сбрасывает его файловый кэш: эти значения не являются тёплым redraw одной иконки.

Задержка входа в Launcher существенна. Текущий холодный поиск проходит существующий PackageManager с проверкой каталогов/пакетов, а отрисовка включает текст и ресурсы. Отдельного аппаратного таймера декодера иконок нет; по этим данным нельзя приписать всё время alpha blending или назвать реализацию оптимальной. Оптимизация холодного пути остаётся отдельной работой с профилированием. FPS, энергопотребление, визуальное качество дисплея и физические жесты этим USB-прогоном не проверены.

## Расчёт ресурсов и host-проверки

FLIM 48×48 с заголовком: A4 — 1168 байт; INDEX8 — `2320+3N` (до 3088); RGB565+A8 — 6928. Clock и Settings с двумя A4-масками занимают 8089 байт payload. У декодера нет полного RGBA-буфера: строка/палитра занимают существующий scratch глифов 4096 байт. На целевой ABI decoder — 36 байт, IconCache — 1088. Добавленные поля основного Core суммарно около 1148 байт до padding, плюс до 3072 байт шести LittleFS caches и дополнительные FILE/VFS/allocator расходы. Это расчёт, **не измеренный отдельный дополнительный peak**: сравнения heap с прошивкой без иконок не выполнялось. Подробности и host timings — [SDK benchmark](../../../platform/docs/ru/FLIM-BENCHMARK.md).

Локально прошли SDK 20/20 и 10/10 без Lua, Flare 24/24, OS host 5/5, tooling 9/9 и проверка Markdown-ссылок. SDK CI прошёл Windows/Linux в обеих Lua-конфигурациях. Положительная SVG-растеризация локально зависит от наличия Cairo; malformed/denied-resource случаи покрыты тестами. Большие каталоги, длинные имена, clipping, повреждённые ресурсы и смена темы проверены host-тестами, не данным аппаратным сценарием.
