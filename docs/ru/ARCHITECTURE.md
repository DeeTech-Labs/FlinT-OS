# Архитектура FlinT OS

Сопровождаемая общая спецификация находится в [Flint IgniteSDK](../../platform/README.md). `platform/` — подмодуль SDK на закреплённом коммите, общий с Flare. Инициализация: `git submodule update --init --recursive`. Общие изменения вносятся в репозиторий SDK.

Аппаратный слой: `components/flint/board/`, `display/`, `ble/`, `core/system.cpp`. Переносимые службы: `platform/src/` и `platform/include/flint/`. Заводские приложения: `platform/system/`, результат компиляции — `platform/factory/`. Контракты разработки: `platform/spec/` и сгенерированные реестры.

Дисплей использует собственный драйвер ST7789 (`display/st7789.cpp`) поверх SPI Master ESP-IDF. Команды питания и gamma, ориентация и смещения принадлежат профилю платы. Драйвер работает только из основной задачи приложения; синхронное завершение SPI/DMA позволяет переиспользовать строковый буфер сразу после записи. Ошибки инициализации и передачи возвращаются вызывающему коду, частично созданные ресурсы освобождаются.

Рендерер IgniteSDK и вычисление изменённой области сохранены. RGB565 framebuffer занимает 134 400 байт: сначала запрашивается PSRAM, затем внутренняя RAM. Предыдущая сцена и строковый DMA-буфер на 560 байт разделяют статическое внутреннее хранилище размером 1352 байт. Сцена читается при вычислении dirty region; затем её время жизни заканчивается и активируется строковый буфер. Сцена восстанавливается только после успешного завершения всех передач. Это экономит отдельные 560 байт без новых аллокаций, дополнительных SPI-передач или изменения размещения ISR в IRAM. Первоначальная заливка и recovery используют то же хранилище независимо от наличия framebuffer. `DISPON` отправляется после заполнения экрана фоном. Recovery сохраняет сообщения, фон, красный текст и позиции строк; вместо шрифта удалённой библиотеки используется встроенный `Body` из IgniteSDK. Полный framebuffer, файловая система и экземпляр Core для recovery не нужны.

Для `esp_driver_spi` в CMake локально включён `CONFIG_COMPILER_OPTIMIZATION_CHECKS_SILENT`. Проверки аргументов и возврат ошибок сохранены; убраны подробные сообщения макросов `ESP_RETURN_ON_*` и `ESP_GOTO_ON_*` внутри этого компонента. Assertion, размещение ISR в IRAM, прочие сообщения SPI и диагностика остальных компонентов не изменены. FlinT продолжает обрабатывать и логировать возвращённые ошибки. Это уменьшает код проверок в IRAM, но сокращает детализацию низкоуровневой диагностики SPI.

Проверки драйвера на компьютере (эмуляция SPI/GPIO, без подключения устройства):

```sh
cmake -S tests/host -B /tmp/flint-display -DCMAKE_BUILD_TYPE=Debug
cmake --build /tmp/flint-display
ctest --test-dir /tmp/flint-display --output-on-failure
```

Тесты сравнивают пиксели с переносимым рендерером и проверяют адресацию, параметры панели, dirty regions, ошибки передачи, очистку ресурсов и recovery при отказе выделения памяти. Они не подтверждают электрические характеристики SPI, визуальную ориентацию, отсутствие tearing или производительность на плате. Lua, LittleFS и форматы пакетов не изменены.


Companion по потребности использует [общий контракт SDK](../../platform/docs/ru/COMPANION.md). [Диагностика и baseline](PERFORMANCE.md).

## BLE availability

Сохранённая `ble_enabled` управляет радио независимо от согласий Companion. Отсутствующее значение мигрирует в `1`; `0` выключает advertising и соединения. Плата не имеет кнопок/touch: включение после выключения выполняется через USB. Bond keys в NVS не стираются. Settings ACK означает принятие persistent политики; actual `ble_state`, `ble_transition_active` и `ble_lifecycle_error` описывают аппаратный переход.

Владелец Core управляет намерением и завершением сессий. Start/stop выполняется временной задачей `ble_policy` со стеком 4096 байт, поскольку vendor `nimble_port_stop` ожидает host task без ограниченного timeout; Core/PackageManager этой задаче недоступны. После выхода host из `nimble_port_run` worker удаляет его через `nimble_port_freertos_deinit`, затем деинициализирует controller/host и освобождает RX queue. Новые задачи не остаются после перехода; обычное idle-обслуживание не добавлено. Ошибки перехода видны в диагностике и автоматически бесконечно не повторяются.

Перед новым стартом проверяются текущие internal free/largest с резервом; `CONFIG_FLINT_BLE_START_MEMORY_REQUIREMENT` по умолчанию 64 KiB сверх общего резерва. Повторные намерения объединяются. При выключении очередь, callbacks и сессия теряют поколение; ответ по BLE может завершиться до stop, ожидание ограничено двумя секундами. Watermark host/worker сохраняет минимум между start/stop циклами.

При локальной проверке на Spark прошли 10 start/stop циклов: около 69 KiB internal освобождается в disabled; PSRAM не меняется, lifecycle errors=0. Это проверка памяти/связи, не измерение тока и не доказательство сохранности существующего bond при повторном pairing.
